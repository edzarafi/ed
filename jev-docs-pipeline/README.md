# Jev + Claude: סיווג, חילוץ ואימות של מסמכים רפואיים

תהליך בשלושה שלבים על 11 מסמכים רפואיים סינתטיים בעברית:

1. **Jev מסווג**: סוג המסמך (9 סוגים), תחום רפואי, דחיפות (0–4) והאם יש פרטים מזהים. כל זה בקריאה אחת.
2. **Claude מחלץ** (`claude-opus-5-5`, structured outputs): אבחנה, ICD-10, תרופות, ערכי מעבדה והמשך טיפול, עם ציטוט ראיה לכל שדה.
3. **Jev מאמת**: לכל שדה שחולץ נשאלת שאלת כן/לא, "האם המסמך תומך בזה?", וההסתברות היא ה-confidence של השדה. בנוסף נבדקת התאמה של ICD לאבחנה, ומתקבל ציון איכות כולל.

אחר כך הקוד מנתב כל מסמך: קבלה אוטומטית, בדיקה מהירה, בדיקה אנושית, מיון ידני או ארכיון.

## הרצה

```sh
pip install -r requirements.txt
jupyter notebook jev_medical_pipeline.ipynb      # או: jupyter nbconvert --execute --inplace ...
```

| מצב | מתי | מה רץ |
|---|---|---|
| `live` | כש-`TYPESAFE_API_KEY` ו-`ANTHROPIC_API_KEY` מוגדרים | Jev ו-Claude אמיתיים |
| `demo` | אחרת | **היוריסטיקה מילולית במקום Jev**, ושחזור של תשובת הייחוס במקום Claude. ממחיש את הזרימה בלבד |

ב-GitHub Actions ‏(`.github/workflows/jev-pipeline.yml`), כל push מריץ את הטסטים ואת המחברת במצב demo. הרצה ידנית עם `mode=live` משתמשת ב-secrets של המאגר.

## קבצים

| קובץ | תוכן |
|---|---|
| `jev_medical_pipeline.ipynb` | המחברת: מעבר מלא על מסמך אחד, הרצה על כל המסמכים, הערכה, עלות |
| `pipeline.py` | השאלות ל-Jev, סכמת החילוץ, ספי הניתוב, ה-backends וההערכה |
| `documents/*.txt` | 11 מסמכים סינתטיים: סיכום אשפוז, מעבדה, מיון, הדמיה (×2), פתולוגיה, הפניה, מרשם, ביקור ילדים, חשבונית, פקס |
| `documents/ground_truth.json` | התשובות הנכונות לכל מסמך: סיווג וחילוץ |
| `tests/test_pipeline.py` | בודקים את הקוד של מצב live מול שני ה-SDK האמיתיים עם HTTP מדומה, ואת הניתוב |
| `make_notebook.py` | מייצר את המחברת |

## מבחן כאוס
עם `INJECT_ERRORS=True` נשתלות שתי טעויות חילוץ: "שבר בגולגולת" בפענוח CT שאומר "ללא עדות לשבר", ומינון אמוקסיצילין כפול. כך רואים אם שלב 3 תופס אותן. במצב live ההערכה סופרת גם טעויות אמיתיות של Claude, כי היא משווה כל שדה לייחוס.
